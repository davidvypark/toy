Create `TOY/TOYShared/Sources/TOYShared/Models/CardTier.swift` with the following:

1. `import Foundation` only -- NO RevenueCat, NO Supabase, NO app-level imports. This is a pure value type.

2. `public enum CardTier: Int, CaseIterable, Comparable, Sendable` with cases:
   - `.free = 0` (up to 5 clips)
   - `.starter = 1` (up to 10 clips)
   - `.group = 2` (up to 25 clips)
   - `.mega = 3` (unlimited, represented as 999)

3. Computed properties:
   - `clipLimit: Int` — returns 5, 10, 25, or `Int.max` (use `.max` for mega, NOT 999 -- Int.max avoids ambiguity between "unlimited display" and "database value")
   - `displayName: String` — "Free", "Starter", "Group", "Mega"
   - `maxParticipantsValue: Int` — 5, 10, 25, 999 (the value to store in Supabase when this tier is purchased)
   - `isPaid: Bool` — `self != .free`
   - `packageIdentifier: String?` — nil for free, "starter", "group", "mega" for paid tiers (matches RevenueCat package identifiers)

4. Static methods:
   - `requiredTier(for clipCount: Int) -> CardTier` — iterates `allCases`, returns first tier where `clipCount <= tier.clipLimit`. Falls back to `.mega`.
   - `fromMaxParticipants(_ maxParticipants: Int) -> CardTier` — maps database column value to tier:
     - `...5` → `.free`
     - `6...10` → `.starter`
     - `11...25` → `.group`
     - `default` (>25, including 999) → `.mega`
   - NOTE: Cards with maxParticipants=8 return `.free` from this method. This is correct for DISPLAY purposes. Enforcement MUST use `card.maxParticipants` directly, NOT `CardTier.clipLimit`. Add a doc comment on `fromMaxParticipants` explaining this grandfathering behavior.

5. Implement `Comparable` with `static func < (lhs:rhs:) -> Bool` comparing `rawValue`.

Then modify `TOY/TOYShared/Sources/TOYShared/Models/Card.swift`:

- Add a doc comment on the parameter: `/// Maximum number of participants. New cards default to 5 (free tier). Legacy cards may have 8 (grandfathered).`
